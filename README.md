# Secret Santa

Web app to organise gift exchanges in groups: create a group, accept join requests, run a fair draw where each member only sees who they give to, and rate the gift you received anonymously.

Built with React 19, Material UI 9, Redux Toolkit, Firebase 13 (Auth + Firestore, optional App Check) and Vite 8.

## Quick path

1. Install Node `^20.19` or `>=22.12`, then `npm install`.
2. `npm run dev` and open <http://localhost:3000>.
3. `npm test` should pass before any change is pushed.

## Scripts

| Script | What it does |
|--------|--------------|
| `npm run dev` | Development server on port 3000 |
| `npm run build` | Production build into `dist/` (served by Firebase Hosting) |
| `npm run preview` | Serves the production build locally |
| `npm test` | Unit and component tests (Vitest + Testing Library) |
| `npm run lint` | ESLint, including the React hooks rules |
| `npm run test:rules` | Drives the real `src/services.js` functions against the Firestore emulator to test the security rules (needs Java 21 and `firebase-tools`) |

CI (`.github/workflows/ci.yml`) runs lint, unit tests, the build and the rules tests on every push to `master` and every pull request.

## Data model

| Path | Content | Who can read it |
|------|---------|-----------------|
| `users/{uid}` | `{ name, email }` | Signed-in users (by id) |
| `groups/{groupId}` | Name, admin, members, requests, draw stage, rating aggregate | Signed-in users |
| `groupNames/{nameId}` | `{ groupId }`: keeps names unique ignoring case and extra spaces | Signed-in users |
| `groups/{groupId}/assignments/{uid}` | Who `uid` gives a present to | Only `uid` |
| `groups/{groupId}/wishes/{uid}` | What `uid` would like to receive | Group members |
| `groups/{groupId}/ratings/{uid}` | The rating `uid` gave to their present | Only `uid` |

Group ids are generated by Firestore; the group name is a normal field, stored NFC-normalised without zero-width characters. `nameId` is the hexadecimal UTF-8 of the lowercase name; the rules only check its format (lowercase hex, at most 1200 characters). Every multi-document change (create, delete, draw, reset, leave) is a single batch or transaction, and `firestore.rules` only allows those exact operations. Delete, draw and reset read the group inside their transaction, so they always use its current members.

`users`, `requests` and `shufflers` never contain duplicates; a group holds at most 50 members and 100 pending requests.

Realtime Database and Cloud Storage are not used: `database.rules.json` and `storage.rules` deny every client access.

## Deploy

```bash
npm run build
firebase deploy --only hosting,firestore,database,storage
```

Run `npm run test:rules` before deploying rule changes. The `database` and `storage` targets only deploy when Realtime Database and Cloud Storage are enabled in the project; until then, drop them from `--only` and deploy them once the products are enabled.

`firebase.json` also sets the hosting security headers (Content Security Policy, `nosniff`, `Referrer-Policy`, `Permissions-Policy`, framing denied) and caching: `/assets/**` is immutable, `index.html` is always revalidated. If you add a third-party script, font or API, add its origin to the CSP.

### App Check (optional)

App Check with reCAPTCHA Enterprise is initialised only when the build has a site key:

```bash
VITE_RECAPTCHA_SITE_KEY=<site key> npm run build
```

Without the variable the app works as before. The CSP already allows the reCAPTCHA origins.

### Firebase console hardening

These settings live in the console, not in the repository:

1. **Authentication → Settings → User actions**: enable *Email enumeration protection*.
2. **Authentication → Settings → Password policy**: require at least 8 characters (the sign-up form already asks for 8).
3. **App Check**: register the web app with reCAPTCHA Enterprise, build with `VITE_RECAPTCHA_SITE_KEY`, watch the metrics and then enforce App Check for Cloud Firestore and Authentication.
4. **Google Cloud console → Billing → Budgets & alerts**: create a budget with email alerts for the project.

## Known limitations

- The draw is computed in the admin's browser, so a technical admin could inspect it while it is generated. Hiding it completely requires a Cloud Function.
- Group search downloads every group name; fine for a small app, not for thousands of groups.
- The server does not verify that `nameId` matches `name` (the rules `lower()` only handles A–Z), so a modified client could reserve a name under a different id.
